# WO-1.0-03 — Lab Map index generator, generated registry and test-impact selection

## 1. Context
Claude Code wastes most of its tokens searching the repository. The lab replaces searching with a generated map built from the module header standard (`CHANGE_CONTROL.md` section 1; `aqis_lab/scoring/wer.py` and `tools/audit/gate.py` are real examples). The current `docs/capabilities/REGISTRY.md` is hand-written; from now on it is generated, and a capability may disappear only with a retirement record. CI runs the generator on `main`; branches never commit its output.

## 2. Your job
`python -m tools.index <build | check | impact>` scans `aqis_lab/`, `tools/` and `tests/aqis_lab/` with Python's `ast` module (never importing the scanned code) and writes small, deterministic markdown files.

## 3. Files you create
| Path | One responsibility | Public API (in words) | Max lines |
| --- | --- | --- | --- |
| `tools/index/scan.py` | Walk the three trees and extract module facts | `scan(repo_root) -> list[ModuleFacts]`: path, docstring, public symbols (name, kind, first signature line, line number), imports resolved to repository modules, parse errors | 300 |
| `tools/index/headers.py` | Parse the header standard | `parse_header(docstring) -> Header`: purpose, capabilities (ID, description, tests), contracts, change-log entries; missing sections listed, never guessed | 200 |
| `tools/index/registry.py` | Build the registry from headers, capability records and retirement records; adopt the hand-written registry; detect disappearance | `build_registry(facts, retired_dir, records_dir, previous_registry_text) -> Registry`; raises `CapabilityRemoved` naming each ID that vanished without a retirement record; `adopt_registry(...)` per B7 and B12 | 300 |
| `tools/index/render.py` | Render the five files deterministically | `render_all(facts, registry) -> dict[path, text]` | 300 |
| `tools/index/impact.py` | Pick the tests affected by a change | `affected_tests(repo_root, base_ref) -> ImpactResult` (pytest arguments, or `all` with the reason) | 250 |
| `tools/index/__main__.py` | Command line | `build [--adopt-registry] [--out DIR]`, `check`, `impact --base REF` | 150 |
| `tests/aqis_lab/index/test_*.py` | Unit tests per module | | 300 each |

## 4. Required behaviour
- **B1** `build` writes `docs/index/MAP.md`, `SYMBOLS.md`, `CALLERS.md`, `TESTMAP.md` and `docs/capabilities/REGISTRY.md` (or into `--out DIR`, same relative layout). Each starts with the line `<!-- Generated by tools.index; do not edit. -->`.
- **B2** MAP: grouped by package; one line per module: path, purpose line, capability IDs, owning WP (the WP of the first change-log entry), and the number of public symbols. At most 2 lines per module.
- **B3** SYMBOLS: public classes and functions (no leading underscore; methods of public classes included as `Class.method`) with their first signature line and `path:line`.
- **B4** CALLERS: for each module, the repository modules that import it (direct importers), sorted.
- **B5** TESTMAP: requirement IDs found in test function names (`test_FR_1_2_03_...` → `FR-1.2-03`; also NFR, AT and DEBT patterns) → test node IDs (`path::function`) → the repository modules those test files import.
- **B6** Registry: one row per capability: ID, module, description, tests, introducing WP, status `active` or `retired`. Retirement records live in `docs/capabilities/retired.d/<CAP-ID>.md` with lines `CAP: …`, `Retired in: WP-…`, `Allowed by: …`. A capability present in the previous committed registry but absent from every header and from `retired.d` raises `CapabilityRemoved`.
- **B7** `--adopt-registry` (one-time migration): parse the hand-written registry; rows whose status already says retired become retirement records; rows absent from headers and not retired are listed in an error, and nothing is written.
- **B8** Output is byte-identical across runs and independent of filesystem order, locale and time.
- **B9** A file that fails to parse is reported as `path:line: message`; the other files are still indexed; the command exits non-zero.
- **B10** `check` builds into a scratch folder and exits 1 if any generated file differs from the committed one, naming the files; exit 0 otherwise.
- **B11** `impact --base REF`: changed files since the merge base → affected modules (the changed modules plus their importers, transitively, inside the repository) → tests: test files that import any affected module, plus tests named for capability tests listed in the affected modules' headers. Print one pytest argument per line. Print `all` with a reason when the change touches `conftest.py`, `requirements/`, `pyproject.toml`, `pytest.ini`, any file under `tests/aqis_lab/` helpers without a test prefix, or more than 25 modules, or when the base ref is missing after one fetch.

- **B12** Pins (amended by Claude after BLK-1.0-05, option 1; the acceptance test checks each):
  1. **Roots.** The command works on the git top-level of the current directory. Every path it prints or writes is repository-relative with `/` separators; nothing depends on the absolute location.
  2. **Trees.** The scan covers `aqis_lab/`, `tools/`, `tests/aqis_lab/` and `kit-staging/` (when present). It skips `__pycache__`, folders whose name starts with `.`, and `tests/aqis_lab/fixtures/` (pytest's `collect_ignore`: data, not modules). Sources are parsed from bytes, so a PEP 263 coding line is honoured.
  3. **Registry sources.** Capabilities come from the headers of modules under `aqis_lab/`, `tools/` and `kit-staging/` only (`CHANGE_CONTROL.md` section 1). A test module's CAPABILITIES section is indexed in MAP but is never a registry source and never counts for E3.
  4. **Capability entries.** An entry starts at an indented `CAP-…:` line; more deeply indented lines that follow continue it and are joined with single spaces. `[tests: a, b]` may span those lines; names keep their order.
  5. **Owning WP.** The first `WP-<n>.<m>` token of the first change-log entry; failing that, `WP-<n>.<m>` taken from its first `WO-<n>.<m>-<k>` token; failing that, `NO CHANGE LOG`.
  6. **Registry table.** The first line is the generated line. The table header is exactly the audit gate's `REGISTRY_COLUMNS`: `| Capability ID | Module | Functions | What it does | Tests | Introduced by | Status |`, then `| --- |` ×7. Rows are sorted by capability ID. A header row is: the ID; the module path in backticks; the module's public top-level functions and classes in source order, each in backticks, joined by `, ` (`module` when it has none); the description with the `[tests: …]` part removed; the tests, each in backticks, joined by `, `; the owning WP; `ACTIVE`. Any `|` inside a cell is written as `&#124;`, so the gate's column split stays exact.
  7. **Capability records.** `docs/capabilities/records.d/<CAP-ID>.md` is exactly seven lines, `CAP: `, `Module: `, `Functions: `, `What it does: `, `Tests: `, `Introduced by: `, `Status: `, each followed by the cell text verbatim, with a final newline. Its row in the registry is those seven cells unchanged. A record whose file name and `CAP:` line differ, or whose ID a header also names, is an error naming both.
  8. **Retirement.** `CAP-…` in `retired.d` keeps its row: cells 2 to 6 come from the previous committed registry's row, and the status is `RETIRED in <Retired in>; allowed by <Allowed by>`. A retirement record for an ID that still appears in a header or record, or that the previous registry lacks, is an error. Records disappear under the same rule as header capabilities (B6).
  9. **Previous committed registry.** `git show HEAD:docs/capabilities/REGISTRY.md`; no previous registry means nothing can have vanished.
  10. **Adoption (replaces the last clause of B7).** `--adopt-registry` reads the working-tree registry with the gate's `parse_registry`. A row whose ID a header names is left to the header. A row whose Status contains `retired` (any case) becomes `retired.d/<ID>.md`, with `Retired in:` set to the first `WP-<n>.<m>` of the Status cell and `Allowed by:` set to the Status cell verbatim. A retired row without such a token is an error. Every other row becomes `records.d/<ID>.md` per pin 7, and its path is printed. Existing records and retirement records are never rewritten; an existing record whose cells differ from the row is an error. Every check runs before anything is written; on any error nothing at all is written. A second run on its own output changes nothing.
  11. **Failures write nothing.** `CapabilityRemoved`, E3 and pin 7 and 8 errors exit 1 and write none of the five files. A parse error (B9) still writes them and exits 1.
  12. **Formats.** MAP: one line per module starting `` - `<path>` ``. SYMBOLS: one line per symbol holding `` `<name>` `` (methods as `` `Class.method` ``), the stripped first source line of its definition and `<path>:<line>`. CALLERS: a `` ## `<path>` `` heading per module, then one `` - `<importer>` `` line per direct importer, or `- (none)`. TESTMAP: a `## <REQ-ID>` heading per requirement ID, then its test node IDs and the modules their files import.
  13. **`check`.** Compares a scratch build with the five files in the working tree. Exit 1 names every differing or missing file, every `NO HEADER` module and every parse error; exit 0 otherwise.
  14. **`impact`.** Changed files are those between the merge base of REF and `HEAD` and the working tree (tracked and untracked, not ignored). Output lines are sorted and unique. A test file selected through imports is printed as its path. A capability test in a file not otherwise selected is printed as `path::name`. The `all` answer is the line `all` followed by a line `reason: <why>`. Exit 0 whenever a selection or `all` is printed (an empty selection prints nothing).
  15. **Command line.** Run as `python -P -m tools.index` with `PYTHONPATH` set to the lab checkout; it must not rely on the current directory being importable.

## 5. Edge cases you must handle
- **E1** A module without a docstring → listed in MAP as `NO HEADER` and counted in the exit status of `check`, not hidden.
- **E2** Relative imports (`from . import x`, `from ..pkg import y`) → resolved to repository paths.
- **E3** A capability listed in two modules → error naming both.
- **E4** A test file importing a module through a package `__init__` → counted as importing that package's modules only if `__init__` re-exports them by name.
- **E5** A deleted module in the diff → its former importers are affected.

## 6. Never
- Never import, execute or evaluate scanned code.
- Never write outside `docs/index/`, `docs/capabilities/` or `--out`.
- Never drop a capability silently.

## 7. When this order is wrong or incomplete
Return QUESTIONS if the existing headers use a format different from `CHANGE_CONTROL.md` section 1 in a way that changes parsing.

## 8. Must-catch behaviours
1. `check` fails when a header changed and the map was not regenerated.
2. A capability removed from a header without a retirement record raises.
3. `impact` selects the tests of a module's importer when the module changes.
4. Two runs give byte-identical output regardless of file order.
5. A syntax error is reported with `path:line` and a non-zero exit, without crashing the scan.
6. SYMBOLS excludes private names and gives `path:line` for each symbol.

## 9. Definition of Done
- **D1** Every file in section 3 exists with its public API and the module header standard.
- **D2** B1 to B12 and E1 to E5 are implemented; point at each.
- **D3** Unit tests build small scratch repositories (with `git init`) as fixtures; no test depends on the real repository's contents.
- **D4** `tests/aqis_lab/index/test_acceptance_wo_1_0_03.py` passes unmodified.
- **D5** No placeholder or swallowed error.
