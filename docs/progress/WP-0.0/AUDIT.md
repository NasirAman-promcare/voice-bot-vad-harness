CRITICAL: 4  ·  MAJOR: 2  ·  MINOR: 2

**Round 6 is fixed.** I re-applied all 23 mutations behind F39 to F43, F46 and BLK-007 myself. Each one now fails a named test. The F01 to F03 mutations (AT-0.0-08) also fail named tests. F44 is documented as an accepted limit and has a parity scenario. The F45 corrections are in, although one of the new sentences is wrong (F54). BLK-007 was resolved the way the owner decided. CI is green on both jobs for the head commit. Every suite and acceptance command gives the expected output.

**The verdict is still FAIL, for the same reason as rounds 4 to 6: the tests are weaker than the code.** This round I ran 38 new mutations on rules that no earlier round had mutated:
- 20 were caught by the fast suite.
- 1 was caught only by the slow suite (P44).
- 1 is equivalent in effect (B14).
- **16 survived every suite.**

I checked each survivor on a concrete input. The unmutated code gives the right answer. The mutated code reports a clean gate or a `PASS` row when it should not.
- **F47, gate test index.** The gate can count functions that pytest never runs as tests: methods of a class not named `Test…`, and functions nested inside another function. Registry check (e) and traceability check (f) then pass on requirements that no test covers.
- **F48, gate parity.** A lower-case `docs/approvals/readme.md` is ignored by the hook, and the gate ignores it too, but no test covers this. Break the rule and the gate passes a guarded edit that the hook rejects. This is also missing from the round 6 "line by line" table.
- **F49, provisioning system step.** Both package checks read the dpkg status text, and neither text check has a test. Without them, a package that dpkg knows but that is not installed is reported `PASS already installed`, and an install that did nothing is reported `PASS installed`.
- **F50, corpus integrity.** Two guards have no test: a clip link that points at other content, and an extraction that was interrupted. Without either one, provisioning reports `sha256 … verified` while the harness would read other or truncated audio.

The code is correct today in every case above. What is missing is tests that would catch a regression.
